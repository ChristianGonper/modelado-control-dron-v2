Este anejo recoge los comandos mínimos necesarios para reconstruir la evidencia
experimental usada en la memoria. No sustituye al \texttt{README.md} del repositorio,
sino que deja una ruta de ejecución compacta.

\subsubsection*{Preparación del entorno}

El proyecto se gestiona con \texttt{uv}. La primera orden sincroniza el entorno
definido por \texttt{pyproject.toml} y \texttt{uv.lock}; la segunda ejecuta las
pruebas disponibles antes de realizar ejecuciones largas.

\begin{verbatim}
uv sync
uv run pytest
\end{verbatim}

\subsubsection*{Ejecución mínima de un escenario}

La ejecución elemental toma un escenario YAML, inicia el vehículo, trayectoria,
controlador, perturbaciones y condiciones de finalización, y escribe dos
archivos:
\begin{itemize}
  \item \texttt{telemetry.json} con la serie temporal y
  \item \texttt{metrics.json} con las métricas agregadas.
\end{itemize}

\begin{verbatim}
uv run simulador-quad run scenarios\hover_clean.yaml --no-visualization

set CASE=results\hover_clean
uv run simulador-quad plot ^
  %CASE%\telemetry.json ^
  --metrics %CASE%\metrics.json ^
  --out %CASE%\figures_report ^
  --profile report --formats png pdf
\end{verbatim}

El mismo comando permite ejecutar escenarios sueltos durante el desarrollo.
Para las figuras finales del anejo visual, sin embargo, se emplean las telemetrías
del dataset clásico y no ejecuciones aisladas.

\begin{verbatim}
uv run simulador-quad run ^
  scenarios\lissajous_clean.yaml ^
  --no-visualization
\end{verbatim}

\subsubsection*{Dataset clásico y expertos PD}

El dataset clásico fija escenarios reproducibles y permite ajustar o fijar
controladores PD por familia. Tras modificar ganancias o criterios de ajuste,
los escenarios deben regenerarse con \texttt{--overwrite} para que las ganancias
incorporadas y los manifiestos vuelvan a ser coherentes.

\begin{verbatim}
uv run python tools\generate_classic_dataset.py ^
  --version v1 --out data\classic_dataset\v1 --overwrite

uv run python tools\tune_classic_pid.py ^
  --dataset data\classic_dataset\v1 ^
  --out data\classic_dataset\v1\pids --workers 8
  %% Ejecuta en paralelo en 8 núcleos de CPU

uv run python tools\run_classic_dataset.py ^
  --dataset data\classic_dataset\v1 ^
  --no-visualization --workers 4

uv run python tools\summarize_classic_dataset.py ^
  --dataset data\classic_dataset\v1
\end{verbatim}

\subsubsection*{Dataset neuronal de fuerza externa}

El controlador neuronal aprende por imitación la fuerza deseada del lazo externo.
Para ello se genera primero una serie de candidatos PD externos, se selecciona
el experto seguro por escenario y se exportan las muestras de
entrada y salida usadas por MLP, GRU y LSTM.

\begin{verbatim}
uv run python tools\generate_outer_force_pid_bank.py ^
  --dataset data\classic_dataset\v1 ^
  --out data\outer_force_pid_bank\v1 --workers 8

uv run python tools\generate_outer_force_dataset.py ^
  --source-dataset data\classic_dataset\v1 ^
  --pid-bank data\outer_force_pid_bank\v1 ^
  --out data\outer_force_dataset\v1

uv run python tools\train_neural_controller.py ^
  --dataset data\outer_force_dataset\v1 ^
  --architecture mlp ^
  --feature-version outer_force_min_v1 ^
  --out data\neural_control\outer_force_mlp_min_v1 ^
  --device auto

uv run python tools\evaluate_neural_controller.py ^
  --dataset data\outer_force_dataset\v1 ^
  --run data\neural_control\outer_force_mlp_min_v1 ^
  --device auto
\end{verbatim}

Las arquitecturas recurrentes se entrenan con el mismo comando, sustituyendo
\texttt{mlp} por \texttt{gru} o \texttt{lstm}. En la evaluación cerrada se pasan
siempre el checkpoint y la normalización correspondientes para evitar mezclar
modelos y escalados.

\subsubsection*{Serie OOD y comparación cerrada}

La serie OOD usada en resultados procede de \texttt{data/neural\_ood/battery\_v1}. 
La auditoría de hélices fijó \texttt{max\_duration\_s}=60\,s en el
generador para que las trayectorias trapezoidales rápidas dispongan de
margen suficiente.

\begin{verbatim}
uv run python tools\generate_ood_battery.py ^
  --out data\neural_ood\battery_v1 ^
  --pid-source-dataset data\classic_dataset\v1 ^
  --overwrite

uv run python tools\run_classic_transfer_dataset.py ^
  --dataset data\neural_ood\battery_v1 ^
  --pid-source-dataset data\classic_dataset\v1 ^
  --pid-family all --include-native --workers 8 ^
  --no-visualization --rerun

uv run python tools\run_neural_outer_force_dataset.py ^
  --dataset data\neural_ood\battery_v1 --split ood ^
  --architecture mlp --device auto --workers 4 ^
  --no-visualization --rerun

uv run python tools\run_neural_outer_force_dataset.py ^
  --dataset data\neural_ood\battery_v1 --split ood ^
  --architecture gru --device auto --workers 4 ^
  --no-visualization --rerun

uv run python tools\run_neural_outer_force_dataset.py ^
  --dataset data\neural_ood\battery_v1 --split ood ^
  --architecture lstm --device auto --workers 4 ^
  --no-visualization --rerun

uv run python tools\summarize_comparison.py
\end{verbatim}

\subsubsection*{Figuras de resultados y anejos}

Las figuras comparativas del capítulo de resultados se regeneran desde el CSV.
Las figuras de telemetría del anejo visual se generan desde el dataset clásico,
donde se guardan las ejecuciones de los PD expertos con parámetros fijados
para train, validación y test. Cuando se quiere ilustrar transferencia cruzada
se usa la carpeta de resultados de transferencia.

\begin{verbatim}
uv run simulador-quad plot-comparison ^
  results\comparison_all_runs.csv ^
  --out TFG_Memoria\Figuras\resultados ^
  --formats pdf png

set ROOT=data\classic_dataset\v1\results\circle
set RUN=circle_g04_P5_combined_s1083
uv run simulador-quad plot ^
  %ROOT%\%RUN%\telemetry.json ^
  --metrics %ROOT%\%RUN%\metrics.json ^
  --out TFG_Memoria\Figuras\resultados\classic_circle_combined ^
  --profile report --formats pdf png

set ROOT=data\classic_dataset\v1\results_transfer
set RUN=circle_g04_P5_combined_s1083_with_pid_lissajous
uv run simulador-quad plot ^
  %ROOT%\%RUN%\telemetry.json ^
  --metrics %ROOT%\%RUN%\metrics.json ^
  --out TFG_Memoria\Figuras\resultados\transfer_circle_lissajous ^
  --profile report --formats pdf png
\end{verbatim}

El mismo comando de \texttt{plot} se ha aplicado a cinco casos nativos:
\texttt{hold\_g05\_P5}, \texttt{circle\_g04\_P5}, \texttt{circle\_g07\_P2},
\texttt{lissajous\_g07\_P5} y \texttt{waypoint\_g03\_P5}. También se ha usado
para una pareja de transferencia del caso circular. En todos ellos, el perfil
\texttt{report} elimina títulos diagnósticos redundantes y conserva ejes,
unidades, leyendas y formato apto para memoria.

\subsubsection*{Archivos de evidencia}

\begin{itemize}
  \item \path{results/comparison_all_runs.csv}: Ejecuciones comparables usadas
    por las figuras principales de resultados.
  \item \path{results/comparison_summary.csv}: Agregación por controlador,
    split y familia.
  \item \path{results/evidence_manifest.csv}: Procedencia de datasets,
    checkpoints y decisiones de inclusión.
  \item Archivos de series temporales de los PD expertos nativos en
    \path{data/classic_dataset/v1/results/*/*/telemetry.json}.
  \item Archivos de métricas y metadatos de esas ejecuciones en
    \path{data/classic_dataset/v1/results/*/*/metrics.json}.
  \item Ejecuciones de transferencia cruzada entre familias de PD en
    \path{data/classic_dataset/v1/results_transfer/*/}.
  \item Directorio de figuras de la memoria en
    \path{TFG_Memoria/Figuras/resultados/}.
\end{itemize}
